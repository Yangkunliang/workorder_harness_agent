# 全局技术规范

## 1. 技术栈

| 分类 | 技术 | 版本 | 说明 |
|------|------|------|------|
| 语言 | Python | 3.11+ | 后端开发语言 |
| 框架 | FastAPI | 0.115+ | Web 框架 |
| ORM | SQLAlchemy | 2.0+ | 数据库访问 |
| 数据库 | MySQL | 8.0+ | 关系型数据库 |
| 缓存 | Redis | 7.0+ | 缓存和会话存储 |
| 配置中心 | Nacos | 2.3+ | 配置管理 |
| 参数校验 | Pydantic | 2.10+ | 数据校验 |

## 2. 目录结构约定

```
project/
├── app/                    # 应用代码
│   ├── api/               # REST API 层（Controller）
│   ├── agent/             # LangGraph 状态机，意图识别、流程编排
│   ├── harness/           # 统一管控：校验、路由、注册中心、容错
│   ├── services/          # 业务逻辑层（Service）
│   ├── database/          # 数据访问层（Repository）
│   ├── config/            # 配置管理（外部配置加载）
│   ├── common/            # 公共组件（常量、异常、日志）
│   └── schemas/           # 数据模型（Pydantic）
├── tests/                 # 测试代码
├── docs/                  # 文档
├── prompt/                # Prompt 模板
├── static/                # 静态资源
└── main.py               # 启动入口
```

### 模块职责说明

| 模块 | 职责 | 类比 Spring |
|------|------|------------|
| `app/api/` | REST API 入口，接收和响应请求 | `@Controller` |
| `app/agent/` | LangGraph 状态机，意图识别、流程编排 | 业务编排层 |
| `app/harness/` | 统一管控：校验、路由、注册中心、容错 | `@Gateway` + 中间件 |
| `app/services/` | 业务逻辑实现 | `@Service` |
| `app/database/` | ORM 数据访问 + Redis 客户端单例 | `@Repository` / `@Entity` |
| `app/config/` | 外部配置加载 | `@Configuration` |
| `app/common/` | 公共组件（常量、异常、日志） | 工具类 |
| `app/schemas/` | Pydantic 数据模型定义 | DTO |

## 3. API 设计规范

### 3.1 路径命名
- 使用小写字母和连字符：`/api/v1/work-orders`
- 版本号放在路径中：`/api/v1/xxx`
- 复数形式表示资源集合：`/api/v1/work-orders`

### 3.2 HTTP 方法
| 方法 | 用途 |
|------|------|
| GET | 查询资源列表或单个资源 |
| POST | 创建新资源 |
| PUT | 更新完整资源 |
| PATCH | 更新部分资源 |
| DELETE | 删除资源 |

### 3.3 响应格式

```json
{
  "code": "00000",
  "message": "操作成功",
  "data": {},
  "timestamp": 1699999999
}
```

## 4. 数据库命名规范

### 4.1 表名
- 小写字母 + 下划线
- 使用复数形式：`work_orders`, `users`

### 4.2 字段名
- 小写字母 + 下划线
- 避免使用保留字
- 外键字段：`{关联表名}_id`

### 4.3 通用字段
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，自增 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |
| deleted_at | DATETIME | 软删除标记 |

## 5. 错误码体系

| 错误码 | 含义 |
|--------|------|
| 00000 | 成功 |
| 10001 | 参数校验失败 |
| 10002 | 缺少必要参数 |
| 20001 | 资源不存在 |
| 50001 | 服务器内部错误 |
| 99999 | 未知错误 |

## 6. 代码风格规范

### 6.1 Python 规范
- 遵循 PEP8 标准
- 使用 `isort` 排序 import
- 使用 `black` 格式化代码

### 6.2 命名规范
- 模块/包名：小写 + 下划线
- 类名：大驼峰 `CamelCase`
- 函数/方法名：小写 + 下划线
- 变量名：小写 + 下划线

## 7. 安全规范

### 7.1 输入校验
- 所有用户输入必须经过 Pydantic 校验
- 防止 SQL 注入（使用 ORM 参数化查询）
- 防止 XSS 攻击（对输出进行转义）

### 7.2 敏感数据
- 密码使用 BCrypt 加密存储
- API Key 不记录日志
- 传输使用 HTTPS

## 8. 日志规范

### 8.1 日志级别
| 级别 | 用途 |
|------|------|
| DEBUG | 详细调试信息 |
| INFO | 一般运行信息 |
| WARNING | 警告信息 |
| ERROR | 错误信息 |
| CRITICAL | 严重错误 |

### 8.2 日志格式
```
[时间] [级别] [模块] [消息]
```

## 9. 工作流配置规范

### 9.1 工作流模式

| 模式 | 值 | 说明 |
|------|-----|------|
| 交互式 | `interactive` | 每步完成后通知用户并等待确认 |
| 自动 | `auto` | 全流程自动执行，无需人工干预 |

### 9.2 环境变量配置

```bash
# 工作流模式
WORKFLOW_MODE=interactive

# 是否发送进度通知
WORKFLOW_NOTIFY=true
```

### 9.3 工作流钩子配置

配置文件路径：`.trae/hooks/workflow.json`

**钩子触发时机**：

| 钩子名称 | 触发时机 | 下一步 Skill |
|----------|----------|--------------|
| `after_prd_created` | PRD 文档生成完成 | `ui-designer` |
| `after_ui_design` | UI 设计完成 | `tech-designer` |
| `after_tech_design` | 技术设计完成 | `task-planner` |
| `after_tasks_created` | 任务拆解完成 | `task-executor` |
| `after_task_execution` | 代码实现完成 | `unit-tester` |
| `after_unit_test` | 单元测试完成 | `e2e-runner` |
| `after_e2e_test` | E2E 测试完成 | `github-deploy` |
| `after_deploy` | 部署完成 | 结束 |

### 9.4 工作流状态流转

```
prd → ui-design → tech → tasks → execution → unit-test → e2e-test → deploy
       ↓            ↓         ↓            ↓              ↓             ↓
      任意阶段失败 → rollback（回滚）
```
